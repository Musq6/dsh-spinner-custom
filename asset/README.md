# asset/

The artwork that gets inlined into `client.js`.

## What may go in here

Only artwork this repository is allowed to redistribute. For a public build that
means one of:

- generated by a script in `tools/` — which is what all seven bundled styles are;
- your own work, licensed however you like;
- third-party work under a licence that permits redistribution, **with the
  licence and attribution recorded somewhere in the repository**. CC0 needs
  nothing; CC-BY needs the credit; most "free" icon sites need neither but
  forbid redistribution of the file itself, which is what inlining does.

If none of those fit, the file belongs in `asset/local/` — see below.

## What the files are

| File | What it is |
|---|---|
| `comet-ring-160x160-15fps-2bpp.png` | The shipped default — shown on a fresh install. |
| `cross-160x160-15fps-2bpp.png` | Two bars growing into a cross. |
| `cutout-160x160-15fps-2bpp.png` | A disc becoming a ring. |
| `dots-160x160-15fps-2bpp.png` | A grid of dots rearranging into a ring. |
| `fold-160x160-15fps-2bpp.png` | A triangle folding through its own centre. |
| `rounding-160x160-15fps-2bpp.png` | A square rounding off into a circle. |
| `spiral-160x160-15fps-2bpp.png` | A ring unwinding into a coil. |

All seven are generated, not drawn: `bash tools/build-spinners.sh` reproduces the
whole set byte for byte, and `tools/make-placeholder.py --shape <name>` is what
draws any one of them.

**Which of them is the default is not positional by accident — it is the first
entry.** The order you hand the files over is the order the picker shows, and the
one at the front is the one a fresh install starts on. Reorder by naming the files
explicitly, or move the selection without touching the order:

```sh
node tools/embed-asset.mjs --fallback=spiral
```

**Replace any of them with your own animation** — drop the file in and rebuild,
or hand the tool exactly the styles you want:

```sh
node tools/embed-asset.mjs asset/your-art.png
```

That last one is worth being clear about: naming a path makes the region *exactly*
that path, so it replaces the whole set rather than adding to it. There is
deliberately no accumulate mode — "which styles are in this build" should be
answerable from the command that built it.

## Naming

`<what it is>-<edge>x<edge>-<fps>fps-<bits>bpp.png` — the name states the specs
so nobody has to open the file to find out. Say `2bpp`, not `4levels`: the level
count and the bit depth are different numbers and the old spelling of that
confused people.

## asset/local/ — gitignored

For artwork you are developing against but cannot publish: a stock clip, a
client's asset, a purchased download. The directory is in `.gitignore`, so
nothing in it is ever committed.

It is a convenience, not a guarantee. `tools/embed-asset.mjs` **copies** the
artwork into `client.js`, and no ignore pattern can hide a copy that lives
inside a tracked file. Inlining from `asset/local/` therefore prints a warning,
and the way to make a tree publishable again is:

```sh
node tools/embed-asset.mjs --clear
```

That empties the generated region of `client.js` and leaves the plugin inert —
no artwork to mask with, so it does not touch the host icon. Re-inline the
bundled set (or your own) when you are ready:

```sh
node tools/embed-asset.mjs                    # every file in asset/, sorted
node tools/embed-asset.mjs asset/your-art.png
```
